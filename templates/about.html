Origem do projeto

2025 — Trabalho acadêmico

O projeto nasceu como trabalho final da disciplina CIN7405 — Projeto de Informatização da Universidade Federal de Santa Catarina (UFSC). O objetivo era propor a informatização de um fluxo informacional real. A escolha foi o Portal da Transparência: dados públicos, volume elevado e navegação complexa. A solução encurtou o caminho entre os dados brutos do SICONFI e a compreensão do cidadão.

{{ current_year }} — VizGov

Após a entrega acadêmica, o projeto migrou para a API oficial do SICONFI (Tesouro Nacional), expandiu a cobertura para os 27 estados e a União Federal (BR), e adicionou série histórica com suporte a backfill por linha de comando via extract.py (--all --start 2015), com throttle entre requisições e detecção automática de arquivos já existentes para evitar retrabalho. Os dashboards passaram a funcionar via AJAX — sem recarregar a página ao trocar UF ou ano. O projeto foi renomeado para VizGov e expandido com mapa coroplético interativo (D3.js + TopoJSON) na página inicial, exibindo a distribuição de receitas e despesas por estado. O seletor de UF foi redesenhado com grid visual, busca por nome/sigla e navegação por teclado.

Como funciona

O pipeline ETL (extract.py) coleta os dados diretamente da API REST do SICONFI (Sistema de Informações Contábeis e Fiscais do Setor Público Brasileiro), mantido pelo Tesouro Nacional. Os relatórios RREO são processados com pandas — receitas do Anexo 03 (categorias de receita corrente, somando as colunas mensais do ano para evitar a janela móvel de 12 meses) e despesas do Anexo 02 (liquidadas até o bimestre, por função orçamentária) — e salvos como JSONs anuais em subpastas por estado (database/{UF}/receitas_YYYY.json e database/{UF}/despesas_YYYY.json).

O Flask serve os dois painéis analíticos via SSR no carregamento inicial e complementa com endpoints AJAX (/api/receitas, /api/despesas, /api/historico/<tipo>, /api/mapa/<tipo>, /api/anos/<tipo>) para atualizações sem reload. O mapa da página inicial consome /api/mapa/<tipo>, que agrega os totais de todos os estados e retorna o ano mais recente com dados disponíveis. Ao subir o servidor, um thread daemon verifica se os dados do ano corrente já existem e os coleta automaticamente em background caso faltem.

Para backfill histórico, o script extract.py pode ser executado standalone pela CLI com os argumentos --all --start 2015 para coletar todos os entes desde 2015, ou --ufs SC SP --anos 2023 2024 para coletas pontuais. O flag --force sobrescreve arquivos existentes. Para o ano corrente, o script detecta automaticamente o melhor bimestre disponível na API (publicação costuma ter 1 bimestre de atraso) e cai em cascata até o bimestre 1 se necessário.
